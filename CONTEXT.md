# Quantum Secured Voting System

An educational demonstration tool that showcases how QKD BB84 and One-Time Pad can theoretically secure a voting system. The voting itself is a minimal toy scenario; the focus is on visualizing and explaining the quantum key distribution protocol.

## Language

### Protocol Actors

**Alice**:
The sender in the BB84 protocol. In this system, Alice maps to the Voter's side — the entity that encodes and transmits qubits.
_Avoid_: Sender, transmitter

**Bob**:
The receiver in the BB84 protocol. In this system, Bob maps to the Election Server — the entity that measures incoming qubits.
_Avoid_: Receiver, server (when referring to the protocol role)

**Eve**:
The eavesdropper in the BB84 protocol. An optional simulated adversary that intercepts and re-transmits qubits, introducing detectable errors.
_Avoid_: Attacker, interceptor

### Protocol Concepts

**BB84**:
The Bennett-Brassard 1984 quantum key distribution protocol. Uses two conjugate bases to encode random bits into qubits, enabling two parties to establish a shared secret key with eavesdropping detection.
_Avoid_: QKD protocol (too generic — BB84 is the specific protocol)

**Qubit**:
A quantum bit transmitted from Alice to Bob during the BB84 protocol. Each qubit encodes one classical bit in a randomly chosen basis.
_Avoid_: Quantum bit (use the abbreviation), photon (in code — "photon" is acceptable in UI labels per the Figma)

**Basis**:
The measurement basis used to encode or decode a qubit. Two bases exist: rectilinear (×) and diagonal (+). When Alice's encoding basis matches Bob's measurement basis, the bit is kept.
_Avoid_: Encoding scheme, measurement type

**Basis Sifting**:
The step where Alice and Bob publicly compare their basis choices and discard qubits where they used different bases. Approximately 50% of qubits survive sifting.
_Avoid_: Reconciliation (used as a subtitle in the UI, but "Basis Sifting" is the canonical term), key sifting

**Sifted Key**:
The shared bit string remaining after basis sifting — only bits where Alice and Bob used the same basis.
_Avoid_: Raw key, matched key

**QBER (Quantum Bit Error Rate)**:
The percentage of errors in the sifted key. A high QBER indicates potential eavesdropping. Estimated by sacrificing a subset of sifted bits (Test Bits) for comparison.
_Avoid_: Error rate (too vague), BER

**Test Bits**:
A configurable subset of sifted key bits that Alice and Bob publicly compare to estimate the QBER. These bits are discarded from the final key after comparison.
_Avoid_: Sample bits, check bits

**Error Threshold**:
The maximum acceptable QBER. If the estimated QBER exceeds this threshold, the key is rejected (eavesdropping assumed).
_Avoid_: Tolerance, limit

**Cascade**:
The error correction protocol applied to the sifted key after QBER estimation passes. Corrects remaining bit errors through iterative parity checks.
_Avoid_: Error correction (too generic when referring to the specific algorithm)

**OTP (One-Time Pad)**:
The encryption method used to secure the vote. The plaintext vote is XOR'd with the BB84-derived key. Provides information-theoretic security when the key is truly random, used once, and at least as long as the message.
_Avoid_: XOR cipher, symmetric encryption

### System Concepts

**Qubit Count**:
The number of qubits transmitted in the BB84 protocol before basis sifting. Must be greater than Target Key Length because approximately 50% are discarded during sifting.
_Avoid_: Transmission size, bit count

**Target Key Length**:
The desired length (in bits) of the final shared key after sifting and error correction. Determines the maximum vote message size for OTP encryption.
_Avoid_: Key size, final key length

**Voter ID**:
An identifier entered by the demo user on the Authentication page (e.g., V-2026-001234). Not validated against a real database — used for labeling votes in the demo.
_Avoid_: Username, voter name

**Election Code**:
A demo passphrase entered alongside the Voter ID (e.g., ELECT2026). Provides UX realism but has no real authentication function in the demo.
_Avoid_: Access code, password

**Session ID**:
A unique identifier generated for each QKD key generation session (e.g., QS-EJPCF84N). Displayed on the Key Generation page. Generated by the frontend in mock mode.
_Avoid_: Run ID, transaction ID

**Transmission Log**:
The per-qubit data table shown on the Key Generation page. Each row shows: index, Alice's bit, Alice's basis, photon polarization, Bob's basis, Bob's measurement result, and whether the qubit is kept after sifting.
_Avoid_: Qubit table, protocol log
